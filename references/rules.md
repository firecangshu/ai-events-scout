# AI 赛事清单 · 筛选与产出规则（杨博 · 长期固化口径）

> 本文件是 skill 的核心知识库。每次刷新赛事清单时，先按本规则逐条筛，再调用
> `scripts/events_table_gen.py` 产出四交付物。规则含「身份/资格维度(0.5)」「地区维度(0.6)」「硬性剔除」「保留门槛」「形式维度」「分类筛选(10)」「产出形态」等。

## 0. 总目标
只出**一份**「还能报 + 即将开启」的赛事清单。不堆量、不收过期项、不收纯学生/纯视频/无入口项。
用户在**武汉**，异地线下需差旅——故「形式」维度是硬筛选维度，不是可有可无的装饰。

## 0.5 身份/资格维度（前置硬约束 · 每次必先设）
- **为什么前置**：不同赛事对参赛身份要求不同——有的**纯学生限定**（仅在校生）、有的设**社会组/社会通道**（社会人士可报）、有的**对所有人开放**、有的**仅企业/团队**。先锁定"目标身份"，才能在检索与筛选时把身份当成硬约束，而非事后发现报不了。
- **目标身份档（四选一，杨博默认 A）**：
  - **A 社会人士/在职/个人开发者（默认）**：保留「所有人可报 / 社会组可报 / 企业·团队可报」，**剔除「纯学生限定」**。
  - **B 在校学生**：保留「所有人可报 / 纯学生限定」，**剔除「仅社会·企业限定（在校生不可报）」**。
  - **C 所有人（最广口径）**：仅按地域/纯视频/无入口等通用规则剔除，保留含学生与社会各类（含 A、B 全部）。
  - **D 企业/团队**：保留「所有人可报 / 企业·团队可报」，**剔除「纯学生限定 / 仅个人可报」**。
- **资格类型标签**（写入 `events_data.json` 的 `eligibility` 字段，便于审计与按身份筛）：
  `纯学生限定` / `社会组可报` / `所有人可报` / `企业·团队可报` / `仅个人可报` / `地域限定(另列)`。
- **执行位置**：这是工作流**第 1 步（检索之前）**。先跑 `scripts/search_plan.py --identity <档> --snap <日期>` 生成"按身份约束的检索清单"，再据此检索；每条候选都要标 `eligibility`，与身份档冲突的（如 A 档遇纯学生限定）直接归入"已剔除"并写原因。
- **与"形式维度"并列**：身份（能不能报）+ 形式（在哪报）共同决定"对你是否可参与"。武汉异地线下需差旅，故两维度都要标。

## 0.6 地区维度（国内 / 国外 / 不限 · 2026-10-19 新增）
不同赛事的举办地/开放范围不同，按「地区」给每条打标，便于按"想打国内赛还是海外赛"筛选。
- **地区标签**（写入 `events_data.json` 的 `scope` 字段）：`国内` / `国外` / `不限`。
- 判定口径：
  - **国内**：主办方 / 落地在中国境内（如厦门、杭州、北京、上海赛，以及天池 / 魔搭 / DataFountain 平台赛）。
  - **国外**：主办方 / 落地在海外（如 Devpost·海外站、芬兰 Since AI 等）。
  - **不限**：不限地区、全球开放（线上全球赛，明确"全球 / 各国均可、除受限地区外"）。海外平台但无国别限制的在线赛可归此类。
- 判定来源优先级：① 页面明示举办地 / 主办方；② 平台性质（Devpost/GitHub 全球平台多为「不限」，若面向特定国家则「国外」）；③ 已核验搜索结论。拿不准归「不限」并在 `note` 注明。
- **地区是分类标签，不是剔除维度**（海外赛也能报，只是差旅 / 时差成本不同）。与形式、身份并列：地区（在哪办/对哪开放）+ 形式（线上还是线下）+ 身份（能不能报）共同刻画一条赛事。

## 0.7 差旅福利 / 外地友好维度（perks · 2026-11-19 新增 · 正向优点标签 · 非门槛）
- **定位铁律**：这是**优点标签，不是硬门槛**。绝不以"是否包路费/食宿"决定收录或剔除——不包路费的赛事照样收进来，只是多一个维度供筛选。它与「纯学生限定/地域限定」那种硬约束性质完全不同。目的：用户在武汉，异地线下需差旅，此维度帮其一眼看出"哪场对异地参赛友好、能省多少差旅"。
- **四档取值**（写入 `events_data.json` 的 `perks` 字段）：
  - `全包` —— 报销路费（机票/火车）+ 提供住宿餐饮
  - `包路费` —— 报销往返交通，食宿自理或未提
  - `包食宿` —— 提供住宿/餐饮，路费自理或未提
  - `不包` —— 明示"差旅/食宿自理""不含交通"
  - `未标注` —— 公开信息未提及（默认；**不臆测**）
- **判定来源**：赛事官网/官宣正文里"报销路费/提供住宿/包食宿/travel covered/free accommodation"等明确承诺；由 `scripts/auto_tag.py` 规则引擎初判 + 人工复核，宁缺勿错，低置信归「未标注」。
- **采集入口**：`search_plan.py` 第三轮「差旅福利补采」query 负责在检索阶段主动采集此类线索（否则数据里永远没有，筛选器形同虚设）。
- **展示**：五份交付物均带差旅福利徽章/列；分享版与速查表顶部有「差旅福利」筛选组，**默认「全部(含不包)」**，点选仅过滤显示、不影响收录。

## 1. 纯学生口径（最重要 · 受 0.5 身份档统辖）
- 本条是身份档 A（默认）的具体落点：**纯学生限定（仅在校生）一律剔除**。
- 设了「社会组 / 社会通道」、社会人士可报的赛事保留（如 iCAN·AI应用创新挑战赛设社会组、各创新创业大赛设社会/企业通道）。
- 判断依据：看官方「参赛对象」里是否有"非在校学生的社会人士 / 在职人士 / 单位或个人"通道，**不要只看赛事品牌名**。
- 若当前身份档为 B/C/D，按 0.5 的 keep/drop 表执行，本条仅当 A 档时等价于"纯学生全剔"。
- **纯学生限定（仅在校生）的赛事一律剔除**，即使挂着大赛品牌（如第十一届华为ICT大赛、湖北省赛等）。
- **设了「社会组 / 社会通道」、社会人士可报的赛事保留**（如 iCAN·AI应用创新挑战赛设社会组、各创新创业大赛设社会/企业通道）。
- 判断依据：看官方「参赛对象」里是否有"非在校学生的社会人士 / 在职人士 / 单位或个人"通道，**不要只看赛事品牌名**。
- **校赛站点陷阱（2026-11-19 华为教训，必查）**：大赛官方链接常同时挂多个「站点」，同一个 information ID 打开可能是**某大学校赛站**（参赛对象"全校学生/本科生/研究生"、纯学生限定、报名早早截止），而不是对全社会开放的主赛道。判定必须：**① 点开报名链接，看页面实际标题与"参赛对象"字段**（不能照抄主赛事介绍里的"企业组/OPC组/高校组"）；② 赛事名/正文出现「XX大学站 / 学院站 / 校园赛 / 全校学生 / 本校学生」= 校赛专属 → 纯学生剔除；③ 标注的资格与链接指向页面必须一致，不一致一律重核。`auto_tag.py` 已把「校赛站点信号」设为最高优先级，高于泛化赛道词。

## 2. 报名截止判定（严谨点 · 腾讯云教训）
- 必须找到**「报名 / 作品征集截止」**字段，用它做时效判定。
- **严禁把「赛事整体周期/结束日」（如 4/15–9/18）当成报名截止**——腾讯云黑客松曾被误标"报名9/18"实为整体赛期、报名早已截止，被判错。核实报错 = 溯源到官方赛程字段。
- 若只给"赛期"无"报名截止"字段（如 ClawHunt 仅"审核制限额100人"+赛期），**按口径剔除**，不要臆测。

## 3. 剔除项（命中任一条即剔除）
- 初赛报名已截止 / 征集已关闭。
- **仅邮箱 / 扫码报名（无网页入口）**：如新致杯·北航（仅邮箱）、店匠（无网页入口）。
- 学生 / 校内 / 地域限定。
- 纯视频内容类（如腾讯SSV科技向善AI视频大赛、各 AIGC 短视频赛）。
- 整体赛程结束日 ≠ 报名截止且无明确报名字段（见第 2 条）。

## 4. 保留项硬性要求（三条全满足才收）
1. 报名仍在进行或即将开放；
2. 有可访问的**网页报名入口**（HTTP 探活 200，用 `scripts/check_links.py` 核验）；
3. 对社会人士开放或有社会通道（见第 1 条）。

## 5. 形式维度（2026-10-18 起长期要求）
每条必须标注 **线上 / 线下 / 混合**，判定来源优先级：
1. 页面明示地点/赛制（如"线下决赛""初赛线上+线下决赛"）；
2. 已核验搜索结论；
3. 平台性质推断（Devpost/GitHub 类全球平台默认线上）。

分类口径：
- **线上**：全程远程（含线上初赛+线上决赛）。
- **线下**：需到指定城市现场（含初赛即现场）。
- **混合**：线上初赛 + 线下决赛 / 线上+线下并行。

配色约定（生成脚本自动套用）：🟢 线上(绿) / 🟠 线下(橙) / 🔵 混合(蓝)。xlsx 与 HTML 均带「形式」列。

## 6. 排序
- 还能报的按「剩余时间从近到远」排。
- 「即将开启」单列（已官宣但报名尚未开放）。当前检索范围一般无此类，若没有就如实写"暂无"。

## 7. 来源与检索策略（建议）
- 搜索引擎：常规 WebSearch 抓公众号/小红书/知乎聚合；关注天池、魔搭、DataFountain、各高校/政府官网。
- 用户指定来源：如 `黑客松.com/this-week`（IDN 解码 `xn--ubtw9y6z8b.com`），逐条按规则筛。
- 每次刷新都做**全网重搜 + 日期戳快照 + 链接存活校验**，过期项移出"还能报"。

## 10. 交付物分类筛选（分享版 + 速查表 · 2026-11-19 更新为四组）
分享版 HTML（主交付物）与速查表顶部带**四组分类筛选器**，点选即客户端过滤，无需改数据：
- **地区**：全部 / 国内 / 国外 / 不限（对应 `data-scope`）。
- **形式**：全部 / 线上 / 线下 / 线上线下（对应 `data-form`，"线上线下"即混合）。
- **人群**：全部 / 不限 / 纯学生（对应 `data-elig`）。
- **差旅福利**（2026-11-19 新增）：全部(含不包) / 全包 / 包路费 / 包食宿 / 未标注（对应 `data-perk`）。**默认全选、不剔除任何赛事**，纯正向筛选。
- 由 `scripts/events_table_gen.py` 自动生成按钮 + JS；每张卡片/行带 `data-scope / data-form / data-elig / data-perk`，并实时显示"显示 X / N 项"。速查表另有区域、关键词搜索与 CSV/Excel 导出（导出列含差旅福利）。
- 默认身份档 A 下「纯学生」项已被前置剔除，故「纯学生」筛选通常为 0；身份档 C（所有人）才会出现纯学生项。
- 清爽表 HTML 与 xlsx 也带「地区 / 差旅福利」列便于离线核对；**交互筛选只在分享版 HTML 与速查表**（清爽表是透明审计参考，保持静态表格）。

### 11.1 小红书引流红线（合规判定，2026-11-14 固化）
依据小红书《交易导流违规管理细则》（2025-03-12 生效）：
- **违规类型 3**：发布其他平台的链接、口令、二维码、小程序等，以及包含上述信息（直接、变形或植入）的图文。
- **违规类型 5**：其他以明示或暗示方式诱导用户至私域或站外三方平台的行为。
- **禁用词**（`xhs-edition/scripts/check_xhs.py` 的 DIVERSION 表，命中即 FAIL）：`http://`、`https://`、`www.`、`链接`、`评论区`、`主页`、`私信`、`微信`、`二维码`、`扫码`、`加我`、`找我`、`扣1`、`口令`、`站外`、`跳转`、`vx`、**`下载`、`网盘`、`附件`、`自取`、`领取`**（笔记不支持文件附件，出现即暗示站外获取文件）。
- **判定示例**：「具体详情可下载表格（含报名网站衔接）」= **不能过**。"可下载表格" = 诱导站外获取文件（类型 5）；"报名网站链接" = 其他平台链接的变形表述（类型 3）。处罚梯度：警告 → 限流 → 扣信誉分 → 永久封号。
- **关键区分**：表格文件本身含链接**不违规**（文件在平台外，用户在自己设备上打开、自己点链接是用户行为）；**违规的是正文/小工具内"去下载表格"这句引导话术**。
- **合规替代话术**（按推荐顺序）：
  1. 「完整详情可点下方『AI赛事百晓生』小工具组件，支持筛选」——小工具是平台内 Red Skill 组件，细则明文豁免平台内组件（小红书商城/购物车/官方留资组件/Red Skill 同列）。
  2. 「完整清单在上方图片里，报名前请各赛事官方页面核对」——不出现 URL/链接字/下载字，读者自行搜索官网。
- **发布方式**：发笔记时通过「发布页 → 添加组件 → Red Skill」挂载已发布的小工具作为报名衔接入口；表格产物（速查表/分享版/清爽表 HTML、xlsx）仅作离线交付物，**不在任何小红书内容（正文/图片/小工具/评论）中引导下载**。
